# 0.1.0-alpha.6 AST 조회와 테스트 구조

컴파일한 템플릿의 AST를 독립된 복사본으로 조회하고, 표현식 사례를 검증하는 단계에 둔다.

| 구성        | 진입점                             | 적용 규칙                                                                            |
| ----------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| AST 스냅샷  | `expression.getAstSnapshot()`      | 호출마다 템플릿 구간, 표현식 노드, 소스 범위를 복사한다.                             |
| 공개 진입점 | `ZSL.compile(source)`              | 컴파일 결과로 `Expression`을 얻는다. 패키지는 `Expression`을 타입으로 공개한다.      |
| 테스트 사례 | 파서, 검사기, 평가기의 `it.each()` | 각 단계 전용 사례는 해당 테스트에 둔다. 파서와 평가기는 공통 리터럴 사례를 사용한다. |

## 구현 범위

- AST는 명시적 스택으로 복사한다. 스냅샷을 바꿔도 평가 결과와 다음 스냅샷에는 영향이 없다. [공개 API](../api.md#ast-조회) · [스냅샷 구현](../../src/expression/expression.ts)
- 파서, 검사기, 평가기, 템플릿의 테스트 파일이 Vitest 사례를 직접 등록한다. 공통 리터럴은 파서와 평가기에서 가져온다. [테스트 사례](../verification.md#테스트-사례) · [공통 리터럴](../../tests/zsl.literal-cases.ts)

## 확인 기준

| 입력 또는 동작                                       | 기대 결과                                                        |
| ---------------------------------------------------- | ---------------------------------------------------------------- |
| `1 + 2`가 든 표현식 구간의 스냅샷에서 첫 리터럴 수정 | 평가 결과는 `'3'`이다. 다음 스냅샷의 첫 리터럴 값은 `1`이다.     |
| 덧셈 연산자가 20,000개인 표현식 구간의 스냅샷 조회   | 복사가 끝나고, 복사한 AST를 평가하면 `'20001'`이다.              |
| `npm test`로 단계별 사례 실행                        | 파서, 검사기, 평가기, 템플릿 사례가 각 테스트 파일에서 실행된다. |

## 남은 작업
