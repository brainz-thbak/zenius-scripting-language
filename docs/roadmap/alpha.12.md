# 0.1.0-alpha.12 오류 진단 범위 보존

오류가 보고한 소스 범위는 해당 오류에만 속하며, 복합 이모지에서 문법 오류가 발생하면 이모지 전체를 가리킨다.

| 구성                     | 적용 규칙                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| 오류의 `issues`와 `span` | 호출자가 이전 오류의 진단을 수정해도 같은 표현식에서 발생하는 다음 오류의 범위는 원문을 가리킨다. |
| `UNEXPECTED_CHARACTER`   | 오류를 일으킨 문자소 전체를 포함하는 UTF-16 범위를 보고한다.                                      |

## 구현 범위

- 공개 진단이 AST의 소스 범위를 참조해 공유하지 않도록 오류 생성 경계에서 범위를 분리한다. 같은 `Expression`의 반복 평가에서 코드와 원문 범위를 검증한다. [공통 오류 클래스](../../src/exception/zsl-error.ts) · [오류 테스트](../../tests/zsl.error.test.ts)
- 렉서가 `UNEXPECTED_CHARACTER`의 끝 위치를 계산할 때 결합 문자와 복합 이모지를 포함한 문자소 경계를 사용한다. 시작과 끝 위치는 템플릿 원문 기준 UTF-16 오프셋으로 반환한다. [렉서](../../src/lexer/lexer.ts) · [공개 오류 API](../api.md#오류와-진단) · [템플릿 테스트](../../tests/zsl.template.test.ts)

## 확인 기준

| 입력 또는 동작                                                                                  | 기대 결과                                                                     |
| ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `${12 / 0}` 평가가 던진 오류의 `issues[0].span.start`를 `0`으로 바꾼 뒤 같은 표현식을 다시 평가 | `DIVISION_BY_ZERO`와 원문 범위 `[7, 8)`                                       |
| `알림 🌐 ${4 + 👩🏽‍💻}` 컴파일                                                                      | `UNEXPECTED_CHARACTER`와 원문 범위 `[12, 19)`. 해당 범위의 문자열은 `👩🏽‍💻`이다. |
