# 0.1.0-alpha.2 사칙연산과 괄호

숫자 리터럴을 피연산자로 사용해 덧셈, 뺄셈, 곱셈, 나눗셈을 계산한다.

| 구성          | 문법     | 적용 규칙                                              |
| ------------- | -------- | ------------------------------------------------------ |
| 덧셈과 뺄셈   | `+`, `-` | 두 연산의 우선순위가 같다.                             |
| 곱셈과 나눗셈 | `*`, `/` | 덧셈과 뺄셈보다 우선한다.                              |
| 괄호          | `(`, `)` | 괄호 안의 표현식을 먼저 묶는다. 괄호를 중첩할 수 있다. |

피연산자에 쓰는 숫자 리터럴은 [alpha.1 리터럴 문법](alpha.1.md)을 따른다.

## 구현 범위

1. EBNF에 `+`, `-`, `*`, `/`의 우선순위와 괄호의 중첩을 정의한다. 우선순위가 같은 연산이 연속될 때의 결합 방향도 정한다. [EBNF](../../spec/zsl.ebnf)
2. 렉서는 연산자와 여는 괄호, 닫는 괄호를 소스 범위가 있는 토큰으로 만든다.
3. 파서는 연산자 우선순위와 괄호에 따라 양쪽 피연산자를 `binary` AST 노드로 묶는다. 입력 끝까지 읽고, 닫는 괄호나 피연산자가 빠진 경우 문법 오류를 반환한다.
4. 평가기는 검사에 통과한 `binary` 노드의 양쪽 값을 계산하고 해당 연산의 결과를 반환한다.

## 확인 기준

| 표현식                             | 기대 결과                    |
| ---------------------------------- | ---------------------------- |
| `1 + 2`, `7 - 3`, `3 * 4`, `8 / 2` | 각각 `3`, `4`, `12`, `4`     |
| `1 + 2 * 3`                        | `7`                          |
| `(1 + 2) * 3`                      | `9`                          |
| `((1 + 2) * (3 + 4))`              | `21`                         |
| `(1 + 2`, `1 +`                    | 소스 범위를 포함한 문법 오류 |

검증 사례의 기준은 [표현식 테스트 데이터](../../tests/zsl.cases.ts)다.
