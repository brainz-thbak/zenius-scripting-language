# 0.1.0-alpha.1 리터럴 문법

표현식에서 숫자, 문자열, 불리언, `null` 리터럴을 읽고 각각의 값을 AST에 담는다.

| 구성   | 문법            | 적용 규칙                                |
| ------ | --------------- | ---------------------------------------- |
| 숫자   | `4`             | 숫자 값으로 해석한다.                    |
| 문자열 | `'event'`       | 따옴표 안의 내용을 문자열 값으로 읽는다. |
| 불리언 | `true`, `false` | 각각의 불리언 값으로 해석한다.           |
| 널     | `null`          | 널 값을 나타낸다.                        |

숫자의 세부 표기와 문자열의 추가 따옴표 및 이스케이프 규칙은 언어 명세에서 정한다. [언어 명세](../language.md)

## 구현 범위

1. 리터럴의 문법과 토큰 범위를 EBNF에 정의한다. [EBNF](../../spec/zsl.ebnf)
2. 렉서는 리터럴을 읽어 값과 소스 범위를 담은 `literal` 토큰을 만든다.
3. 파서는 토큰을 `literal` AST 노드로 만들고, 표현식 하나를 읽은 뒤 입력이 끝났는지 확인한다.
4. 평가기는 검사에 통과한 리터럴 노드의 값을 돌려준다.

## 확인 기준

유효한 표현식을 파싱하면 AST 노드가 리터럴의 값, 타입, 소스 범위를 보존한다. 평가기는 표의 값을 원래 타입으로 반환한다.

| 표현식          | 기대 결과                    |
| --------------- | ---------------------------- |
| `4`             | 숫자 `4`                     |
| `'event'`       | 문자열 `event`               |
| `true`, `false` | 각각의 불리언 값             |
| `null`          | `null`                       |
| `'event`        | 소스 범위를 포함한 문법 오류 |
