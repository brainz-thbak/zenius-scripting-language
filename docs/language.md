# 언어 명세

## 템플릿

ZSL 템플릿은 일반 텍스트와 `${...}` 표현식 구간으로 구성된다. 일반 텍스트에서 `${` 바로 앞에 역슬래시가 연속하면 두 개당 역슬래시 한 개를 출력한다. 역슬래시가 하나 남으면 그 역슬래시를 소비하고 `${`를 일반 텍스트로 출력한다. 역슬래시가 없거나 짝수 개이면 `${`가 표현식 구간을 연다. 일반 텍스트의 다른 위치에 있는 역슬래시와 중괄호는 보존한다. [EBNF](../spec/zsl.ebnf)

템플릿 원문 `\${42}`는 `${42}`를 출력하고, `\\${42}`는 역슬래시 한 개와 표현식 결과를 붙여 `\42`를 출력한다.

표현식 구간은 문자열 리터럴 밖에서 처음 만나는 `}`에서 닫힌다. 문자열 리터럴 안에서는 리터럴의 이스케이프 규칙을 적용한다. 닫는 구분자가 없으면 `${`부터 템플릿 끝까지를 문법 오류 범위로 보고한다. 진단 범위는 이스케이프를 처리하기 전의 템플릿 원문을 기준으로 한다.

각 구간에는 표현식 하나가 들어간다. 템플릿은 표현식의 값을 문자열로 바꿔 원래 위치에 삽입한다. `String()`이 `1e-7`처럼 음의 지수로 표시하는 양의 `number` 값은 소수점을 옮겨 지수 없는 10진 표기로 출력한다. 나머지 값은 `String()`의 결과를 사용한다. `${4 + 6}`만 있는 템플릿은 문자열 `'10'`을, `${null}`은 문자열 `'null'`을 반환한다.

## 표현식

토큰 사이와 표현식 앞뒤에 스페이스, 탭, LF, CR을 사용할 수 있다. 표현식 뒤의 공백을 읽으면 구간이 끝나야 한다. [EBNF](../spec/zsl.ebnf)

표기법을 처음 읽을 때는 [ZSL의 EBNF 읽는 법](ebnf.md)을 참고한다.

### 리터럴

- 숫자는 부호 없는 10진 정수 또는 소수다. 소수점 양쪽에는 숫자가 한 자리 이상 있어야 한다. 선행 0을 허용한다. 지수 표기와 10진수 이외의 진법은 허용하지 않는다. JavaScript `number`로 변환했을 때 값이 유한해야 한다. 소수점 없는 정수가 `Number.MAX_SAFE_INTEGER`를 초과하면 `bigint`로 값을 정확히 보존한다. 안전한 정수와 소수점이 있는 리터럴은 `number`로 읽는다.
- 문자열은 작은따옴표 또는 큰따옴표로 묶는다. 여는 따옴표와 닫는 따옴표는 같은 종류를 사용한다. `\\`, `\'`, `\"`, `\n`, `\r`, `\t`는 각각 역슬래시, 작은따옴표, 큰따옴표, LF, CR, 탭으로 읽는다. U+0000부터 U+001F까지의 문자를 문자열에 직접 쓸 수 없다.
- `true`, `false`, `null`은 소문자로 쓴다.

소스 범위는 원문의 0부터 시작하는 UTF-16 코드 단위 오프셋이다. 시작 위치를 포함하고 끝 위치를 제외한다. 리터럴의 범위는 앞뒤 공백을 제외한다. 문자열의 범위에는 양쪽 따옴표와 이스케이프 표기가 포함된다. 예를 들어 `${ 'event' }`의 문자열 범위는 `[3, 10)`이다. 단독 표현식에서 닫히지 않은 문자열의 오류 범위는 여는 따옴표부터 입력 끝까지다.

파서와 평가기는 같은 사례로 리터럴 값을 확인한다. [공통 리터럴 사례](../tests/zsl.literal-cases.ts)

### 연산자 우선순위와 결합 방향

같은 행의 연산자는 우선순위가 같다. 표 위쪽에 있는 연산자가 먼저 묶인다.

| 연산자   | 결합 방향  |
| -------- | ---------- |
| `*`, `/` | 왼쪽부터   |
| `+`, `-` | 왼쪽부터   |
| `&&`     | 왼쪽부터   |
| `\|\|`   | 왼쪽부터   |
| `??`     | 왼쪽부터   |
| `? :`    | 오른쪽으로 |

`??`는 `&&`, `||`와 한 표현식에 쓸 수 있다. 예를 들어 `false ?? false || true`는 `false ?? (false || true)`와 같이 묶인다. 괄호는 내부 표현식을 먼저 묶고 중첩할 수 있다. 괄호로 감싼 AST 노드의 소스 범위에는 양쪽 괄호가 포함된다.

### 사칙연산과 괄호

사칙연산의 양쪽 값은 숫자여야 한다. 한쪽 이상이 `bigint`이고 양쪽 값이 모두 정수이면 덧셈, 뺄셈, 곱셈과 나누어떨어지는 나눗셈은 `bigint`로 계산한다. 이때 `number` 피연산자는 JavaScript에 저장된 정수 값을 사용한다. 나머지 사칙연산은 두 값을 `number`로 변환해 계산한다.

평가기는 숫자가 아닌 피연산자의 범위에 검사 오류를 낸다. 0으로 나누면 나누는 수의 범위에 오류를 낸다. 결과를 `number`로 변환했을 때 유한하지 않으면 연산 전체의 범위에 오류를 낸다.

### 삼항 연산, 논리 연산과 널 병합

| 연산                                   | 평가 규칙                                                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `조건 ? 참일 때의 값 : 거짓일 때의 값` | 조건을 먼저 평가한다. 조건이 참이면 `?` 뒤의 가지를, 거짓이면 `:` 뒤의 가지를 평가해 반환한다. 선택한 가지만 평가한다. |
| `a && b`                               | 왼쪽 값이 `false`이면 `false`를 반환한다. `true`이면 오른쪽 값을 평가해 반환한다.                                      |
| `a \|\| b`                             | 왼쪽 값이 `true`이면 `true`를 반환한다. `false`이면 오른쪽 값을 평가해 반환한다.                                       |
| `a ?? b`                               | 왼쪽 값이 `null`이면 오른쪽 값을 평가해 반환한다. 그 외에는 왼쪽 값을 반환한다.                                        |

삼항 연산에는 양쪽 가지에 다른 삼항 연산을 넣을 수 있다. 예를 들어 `false ? 1 : true ? 2 : 3`은 `false ? 1 : (true ? 2 : 3)`과 같다.

조건과 실제로 평가한 논리 연산의 피연산자는 불리언이어야 한다. 불리언이 아닌 값이 나오면 해당 조건이나 피연산자의 소스 범위에 검사 오류가 발생한다.

### 함수 호출

함수 이름은 ASCII 영문자 또는 `_`로 시작하며, 뒤에 ASCII 영문자, 숫자 또는 `_`를 붙일 수 있다. `true`, `false`, `null`은 리터럴 전용이다. 함수 이름 뒤에 괄호를 쓰고, 괄호 안의 인자는 쉼표로 구분한다. 각 인자에는 함수 호출을 포함한 표현식 하나를 쓸 수 있다. 빈 인자 목록을 파싱할 수 있으며, 쉼표 앞뒤에는 인자가 필요하다. 호출의 소스 범위에는 함수 이름부터 닫는 괄호까지 포함된다.

검사기는 연산자가 평가할 가지를 선택하기 전에 모든 함수 호출을 원문의 순서대로 확인한다. 함수 이름은 대소문자를 구분한다. 등록되지 않은 이름이나 최소 인자 개수를 충족하지 못하는 호출에는 호출 범위에 검사 오류가 발생한다. 평가기는 실제로 실행하는 호출의 인자를 왼쪽부터 평가한다.

연산자와 함수 호출의 단계별 범위는 로드맵에 있다. [로드맵](roadmap/)

표현식 문법, 호출 검사, 평가 결과는 단계별 테스트에서 확인한다. [파서 테스트](../tests/zsl.parser.test.ts) · [검사기 테스트](../tests/zsl.checker.test.ts) · [평가기 테스트](../tests/zsl.evaluator.test.ts)

## 데이터 접근

`GET`은 두 개 이상의 인자를 받는다. 각 인자의 평가 값은 문자열이어야 한다. 첫 인자는 컨텍스트의 키이고, 나머지 인자는 차례로 읽을 속성 이름이다. 컨텍스트가 `{ event: { severity: 6 } }`이면 `GET('event', 'severity')`의 결과는 `6`이다. 컨텍스트를 생략하면 빈 객체를 사용한다.

조회 규칙은 일반 객체와 배열로 구성된 컨텍스트 데이터에 적용한다. `GET`은 컨텍스트의 루트 키와 경로의 각 속성 이름에 같은 규칙을 적용한다. 먼저 이름이 정확히 일치하는 자체 속성을 선택한다. 정확히 일치하는 이름이 없으면 요청한 이름과 자체 문자열 속성 이름을 Unicode NFC로 정규화해 비교한다. 열거 불가능한 자체 속성도 비교 대상에 포함한다. 정규화한 이름이 일치하는 후보가 하나면 그 속성을 선택한다.

일치하는 속성이 없거나 NFC 비교에서 후보가 여러 개면 `null`을 반환한다. `GET`은 선택한 자체 데이터 속성에 저장된 값만 읽는다. 선택한 속성이 접근자이거나 값이 `undefined`이면 `null`을 반환한다. 경로가 남은 상태에서 문자열이나 숫자 같은 원시 값에 도달해도 `null`을 반환한다.

마지막 값이 문자열, 불리언, `null` 또는 유한한 JavaScript `number`이면 그대로 반환한다. `bigint`를 포함한 그 외의 값은 호출 범위에 검사 오류를 낸다. 문자열로 평가되지 않은 인자는 해당 인자의 범위에 검사 오류를 낸다. [공개 API](api.md)

## 허용 범위

변수 선언, 할당, 함수 선언, 제어문, 점 표기와 대괄호 표기를 통한 직접 속성 접근을 문법에서 제외한다. 검사기는 호출 구문에 있는 함수 이름이 등록돼 있는지 확인한다. ZSL의 표현식에는 전역 변수, 미등록 함수, 라이브러리 객체와 메서드를 노출하지 않는다. 날짜 접근을 지원할 때는 등록 목록에 전용 함수를 추가한다.
