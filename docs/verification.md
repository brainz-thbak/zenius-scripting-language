# 검증 가이드

Node.js 24 이상에서 `npm ci`로 의존성을 설치한다. 실행 명령의 기준은 [`package.json`](../package.json)이다.

| 확인할 대상        | 명령                   | 확인 기준                                                           |
| ------------------ | ---------------------- | ------------------------------------------------------------------- |
| 소스와 테스트 타입 | `npm run typecheck`    | TypeScript 진단 없이 종료한다.                                      |
| 린트 규칙          | `npm run lint`         | 명시적 `any`를 비롯한 오류를 확인한다.                              |
| 포맷               | `npm run format:check` | 파일을 수정하지 않고 포맷 차이를 확인한다.                          |
| 동작 사례          | `npm test`             | 변경한 단계의 사례가 발견되고 실행되는지 확인한다.                  |
| 빌드               | `npm run build`        | `dist/index.mjs`, `dist/index.cjs`와 대응하는 타입 선언이 생성된다. |
| npm 패키지         | `npm pack --dry-run`   | 공개 진입점과 타입 선언이 들어 있고 테스트 파일은 제외된다.         |

## 단계별 동작 검증

- 파서는 표현식 구간 전체를 읽는지, 유효하지 않은 문법을 거부하는지 확인한다.
- 검사기는 파서를 통과한 호출이 등록 목록에 없거나 최소 인자 개수를 충족하지 않으면 오류를 내는지 확인한다.
- 평가기는 같은 표현식 AST를 서로 다른 컨텍스트로 평가하고, `GET`의 경로 조회와 오류의 소스 범위를 확인한다. 템플릿은 텍스트와 표현식이 합쳐진 문자열을 확인한다.
- 공개 타입을 바꾸면 빌드된 패키지를 ESM 및 CommonJS 프로젝트에서 참조해 두 진입점의 선언을 확인한다.

## 테스트 스위트 연결

표현식 사례는 [`zsl.cases.ts`](../tests/zsl.cases.ts)에 있다. [파서 테스트](../tests/zsl.parser.test.ts)는 문법 오류를, [검사기 테스트](../tests/zsl.checker.test.ts)는 파싱을 통과한 호출의 검사 오류를 확인한다. [평가기 테스트](../tests/zsl.evaluator.test.ts)는 평가 결과와 평가 중 오류를 확인한다. `npm test`는 `--passWithNoTests`를 사용하므로 출력에서 실행된 테스트 수를 확인한다.

문서만 수정했다면 상대 링크가 가리키는 파일과 문서에 적은 명령을 확인하고 포맷 검사를 실행한다.
