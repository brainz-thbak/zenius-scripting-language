# 0005 ZSL 인스턴스별 입출력 길이 제한 설정

## 배경

같은 애플리케이션에서 여러 용도의 템플릿을 처리할 수 있다. 용도마다 허용할 원문과 평가 결과의 길이가 다를 수 있다.

## 결정

- `new ZSL(options?)`는 `maxInputLength`와 `maxOutputLength`를 받는다. 각 인스턴스는 생성할 때 설정값을 저장한다. 컴파일된 `Expression`에도 해당 인스턴스의 출력 한도를 적용한다.
- 길이는 `String.length`가 반환하는 UTF-16 코드 단위로 잰다. 소스 범위와 같은 단위다.
- 각 한도는 0 이상의 안전한 정수다. 한도를 생략하거나 `undefined`로 두면 입력은 16,384, 출력은 65,536 UTF-16 코드 단위를 기본값으로 적용한다. 출력에는 `GET`이 컨텍스트에서 읽은 문자열도 포함되므로 출력 기본 한도를 더 크게 둔다.
- `compile()`은 입력이 문자열인지 확인한 뒤 템플릿 원문의 길이를 검사한다. 한도를 초과하면 파싱 전에 `INPUT_LENGTH_LIMIT_EXCEEDED`를 던진다.
- `evaluate()`는 텍스트나 문자열로 바꾼 표현식 결과를 이어 붙이기 직전에 누적 길이를 검사한다. 한도를 초과하면 `OUTPUT_LENGTH_LIMIT_EXCEEDED`를 던지고 평가를 중단한다.
- 운영 환경에 따라 한도를 바꾸는 소비처는 환경변수나 설정 파일을 읽어 생성자 옵션으로 전달할 수 있다.

## 검토한 방식

| 설정 방식                            | 적용 범위와 사용 조건                                                                          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 생성자 옵션                          | 용도별 인스턴스에 정책을 둔다. 같은 프로세스에서 서로 다른 한도를 함께 쓸 수 있다.             |
| 라이브러리에서 환경변수 읽기         | 프로세스 단위의 운영 설정에 적합하다. 여러 용도의 한도를 표현하려면 추가 규약이 필요하다.      |
| `ZSL.config` 전역 설정               | 여러 호출부가 설정 상태를 공유한다. 정책 변경 시점과 테스트 간 상태 관리가 필요하다.           |
| `compile()`·`evaluate()` 호출별 옵션 | 요청마다 한도가 달라질 때 적합하다. 같은 정책을 쓰는 호출에서도 한도를 반복해서 전달해야 한다. |
