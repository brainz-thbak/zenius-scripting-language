# 0009 숫자 리터럴과 산술의 정밀도

## 배경

ZSL은 큰 정수 리터럴 `9007199254740992`와 `9007199254740993`을 구별해야 한다. JavaScript `number`는 두 리터럴을 같은 값으로 읽는다. Splunk 검색의 `eval`에서도 64비트 부동소수점 연산 때문에 `9007199254740991 + 1`과 `9007199254740991 + 2`가 같은 결과를 낸다. [alpha.14 로드맵](../roadmap/alpha.14.md) · [Splunk `eval` 예제](https://help.splunk.com/en/splunk-enterprise/search/spl-search-reference/10.2/search-commands/eval#rounding-with-values-outside-of-the-range-of-supported-values)

## 결정

- 안전한 정수와 소수점이 있는 리터럴은 `number`로 읽는다. 안전 정수 범위를 넘는 소수점 없는 리터럴은 원문에서 `bigint`로 읽는다. 리터럴을 `number`로 변환했을 때 값이 유한해야 한다. [리터럴 명세](../language.md#리터럴)
- 양쪽 값이 정수이고 한쪽 이상이 `bigint`이면 덧셈, 뺄셈, 곱셈과 나누어떨어지는 나눗셈을 `bigint`로 계산한다. 이때 `number` 피연산자는 JavaScript에 저장된 정수 값을 사용한다. 그 외의 연산은 `number`로 계산한다. [사칙연산 명세](../language.md#사칙연산과-괄호)
- `GET`은 컨텍스트에서 받은 유한한 `number`를 그대로 반환한다. 이미 `number`로 변환된 값의 정밀도는 컨텍스트에 저장된 값으로 정해진다. [데이터 접근 명세](../language.md#데이터-접근)

## 근거와 결과

큰 정수 리터럴을 원문에서 `bigint`로 읽으면 값의 차이를 보존하면서 두 `number` 사이의 계산 규칙을 유지할 수 있다. 정확한 십진수나 유리수 연산을 도입하려면 새 숫자 표현과 나눗셈 결과의 출력 규칙을 정해야 한다.

두 피연산자가 모두 `number`이면 계산 결과가 안전 정수 범위를 넘어도 `number`로 남는다. `9007199254740991 + 2`는 `9007199254740992`로 반올림된다. 소수 리터럴을 읽거나 소수 연산을 할 때도 반올림이 발생할 수 있다. 예를 들어 `0.1 + 0.2`의 결과는 `0.30000000000000004`다.
